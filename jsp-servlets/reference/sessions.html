Explaining Project 5, reference sheet

Sessions cheat sheet

How Project 5 remembers who is logged in, and how it protects that memory.

HTTP “is by design a stateless protocol”: Servlet spec, chapter 7.

HTTP forgets between requests. A session is a small store on the server for one visitor (HttpSession). Tomcat gives the browser its ID in the JSESSIONID cookie, the browser sends it back on every request, and Tomcat uses it to find the session. Project 5 stores one thing there: the User ID.

The real headers

# First visit to /login: login.jsp joins a session by default
Set-Cookie: JSESSIONID=71934BB6…; Path=/jsp-login; HttpOnly; SameSite=Lax
# Correct login: a brand-new ID, then a redirect
Set-Cookie: JSESSIONID=4EE2E79B…; Path=/jsp-login; HttpOnly; SameSite=Lax
Location: /jsp-login/home
# Every later request
Cookie: JSESSIONID=4EE2E79B…
# /home response
Cache-Control: no-store

getSession(true): find the session, or create one. getSession(false): find it, or return null.
