Explaining Project 5, reference sheet

Project 5 flow charts

Three views of the same app: the pages a user moves through, what happens inside one request, and what happens when the app starts.

Read them in order. Each one zooms in on the one before. The colours are the same layer colours as the lessons: browser Tomcat servlets and filters JSP pages database.

What the user sees

The app has five pages, and Log in is the hub: every path ends back there. Each diamond is a check that Java code makes after the user submits a form; the class that makes it is named underneath.

Inside one request

Zoom into any arrow above and you find the same machinery. Tomcat passes the request through two filters, a servlet decides what to do, UserDao talks to the database, and the answer goes back as an HTML page or a redirect.

Before the first request: startup

One thing happens before any user arrives. When Tomcat starts the app, a listener sets up the database once and shares a single UserDao with every servlet.

Say it in four sentences

Practise this out loud with the 60-second timer in lesson 1.

“Project 5 is an MVC web app running on Tomcat: servlets are the controllers, JSPs are the views, and a DAO holds all the SQL. At startup, a listener connects to an embedded H2 database over JDBC, creates the users table if it’s missing, and shares one UserDao with every servlet. Each request passes a security-headers filter, and private pages also pass a login check; then a servlet validates the input, calls UserDao, and either forwards to a JSP or redirects the browser. Users move between five pages, Log in, Create an account, Account created, Reset password, and Home, and every path ends back at Log in.”
